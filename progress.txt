ARCHITECTURAL NOTE — drawing vs widgets:
  Each drawing item uses the same storage model as a widget (keyed object
  in a Yjs Y.Map) but is NOT rendered through WidgetWrapper. The SVG layer
  owns all drawing item interaction. Two separate Y.Maps in the same Y.Doc:
    doc.getMap('items')    — widgets → boardStore
    doc.getMap('drawings') — drawing items → drawingStore
  Both share the same IndexedDB and WebSocket providers from useYjsDocument.

BUGS FIXED (2026-02-21):
  1. Coordinate offset: screenToBoard was using window.innerHeight/2 as the Y
     center, but the board-viewport starts at top: 48px, putting the board
     origin at vh/2 + 48 in screen coordinates. Fixed by adding an optional
     viewportEl ref parameter to useCanvasCoords; all four coordinate functions
     (screenToBoard, boardToScreen, getViewportCenter, getViewportBounds) now
     read viewportEl.getBoundingClientRect().top dynamically. BoardCanvas passes
     its viewportRef when constructing the coords object.
     usePanZoom.applyZoom had the same incorrect baseline and was fixed to use
     the same viewport top offset so zoom-to-cursor stays consistent.
     Files changed: useCanvasCoords.ts, usePanZoom.ts, BoardCanvas.vue
  2. Widgets selectable in drawing mode: WidgetWrapper had no awareness of
     drawingMode. Selected widgets (z-index: 11) could render above the SVG
     capture rect, causing their @pointerdown to fire instead. Fixed by reading
     drawingMode from useUiStore and adding pointer-events: none to the wrapper's
     inline style whenever drawingMode is true.
     Files changed: WidgetWrapper.vue

════════════════════════════════════════════════════════════════
ADDITIONAL FIXES & IMPROVEMENTS (post-phase bug fixes)
════════════════════════════════════════════════════════════════

1. Widget component resolution (critical bug)
   Problem:  <component :is="'TodoList'"> renders as unknown HTML element
             <todolist> because Nuxt auto-import is compile-time only;
             string names don't resolve at runtime.
   Fix:      Replaced string map with explicit component object imports in
             board page. <component :is="StickyNote"> always resolves.

2. StickyNote hex.slice crash (defensive fix)
   Problem:  accentColor computed called hex.slice() but color from stale
             IndexedDB data could be non-string (null/object/number).
   Fix:      typeof hex !== 'string' guard before slice; optional chaining
             on .content throughout StickyNote.

3. Teleport target missing (WidgetOptions)
   Problem:  .widget-slot-{id} lives inside v-if="isSelected" so it doesn't
             exist in the DOM when WidgetOptions mounts → Vue Teleport warns
             and drops the content.
   Fix:      Changed context-toolbar from v-if → v-show so the slot target
             div is always in the DOM. Added defer to <Teleport> as backup.

4. StickyNote background not showing
   Problem:  background: var(--note-bg) in scoped CSS failed to read the
             inline CSS custom property in some Vue/Vite build configurations.
   Fix:      Moved background to direct inline :style="{ background: color }".
             Added CSS fallback background: #FDE68A as safety net.

5. Widget selection flicker
   Problem:  WidgetWrapper stops pointerdown bubbling but canvas deselects on
             click. Sequence: pointerdown→select, click→deselectAll(). Widget
             appeared to flash selected then immediately deselect.
   Fix:      Added @click.stop to .widget-wrapper so click events never reach
             the canvas's deselect handler.

6. PrimeVue ColorPicker collision
   Problem:  @primevue/nuxt-module globally registers a ColorPicker component.
             Our app/components/ui/ColorPicker.vue is auto-named UiColorPicker
             by Nuxt. <ColorPicker> in StickyNote resolved to PrimeVue's
             native browser color picker popup instead of our swatches.
   Fix:      Added explicit import in StickyNote:
             import NoteColorPicker from '~/components/ui/ColorPicker.vue'
             and used <NoteColorPicker> in the template.

7. Color sync between picker and note background
   Problem:  saveContent (debounced) and updateColor were spreading stale
             reactive proxy content which could overwrite each other's changes.
   Fix:      Each function explicitly reads only the field it needs at call
             time: saveContent reads current color, updateColor reads current
             text. No spreading of the whole content object.

8. ColorPicker redesign
   Changed:  Replaced free-form palette (10 colors, Tailwind ring classes) with
             7 curated note-appropriate swatches (Yellow, Red, Amber, Mint, Sky,
             Violet, Stone). Active swatch shows an outline ring in its own
             color (not blue). Pure scoped CSS, no Tailwind dependency.

DRAWING MODE IMPROVEMENTS (2026-02-25)
════════════════════════════════════════════════════════════════

1. Chrome SVG rendering fix
   Problem:  Drawings/shapes were invisible in Chrome-based browsers but
             rendered correctly in Firefox. Root cause: .svg-layer had
             width: 0; height: 0 in CSS. Chrome clips SVG paint to the
             element's bounding box even when overflow: visible is set;
             Firefox is more lenient. Zero dimensions = nothing painted.
   Fix:      Removed width: 0; height: 0 from .svg-layer. position: absolute
             with inset: 0 now lets the SVG fill origin-wrapper (20000×20000 px)
             correctly. overflow: visible still handles content at negative
             coordinates.
   Files:    app/components/board/SvgLayer.vue

2. Drawing item rotation (R key)
   Feature:  Items in drawing selection mode can now be rotated.
   - shared/types/drawing.ts: added rotation?: number to DrawingBase
     (degrees, 0 = upright, stored in Yjs with the item)
   - SvgLayer.vue script:
     - isRotateMode ref: toggled by R key, auto-clears on deselect/tool change
     - rotateInteraction ref: tracks drag start angle + per-item orig rotations
     - rotateHandleInfo computed: circle 32px above unrotated selection bbox top;
       returns null when not in rotate mode
     - onRotateHandlePointerDown/Move/Up: pointer-capture drag computes
       atan2(cursor - center) each frame, applies origRot + delta per item;
       Shift key snaps delta to nearest 15°; wrap-around normalized to [-180, 180]
     - onKeydown: R/r (any drawing tool, any selection) toggles rotate mode;
       if not already on select tool, switches to it first automatically
     - Escape: exits rotate mode before deselecting (priority chain:
       rotate mode → drill-in mode → deselect)
     - watch(activeTool): clears rotate mode when tool changes
   - SvgLayer.vue template:
     - Each item <g> gets transform="rotate(deg, cx, cy)" when rotation is set
     - Resize handles suppressed when item.rotation is non-zero (resize logic
       assumes axis-aligned bbox; mixed rotate+resize deferred)
     - Rotation handle UI: dashed connector line + white/blue circle with
       cursor: grab; rendered after committed items, before in-progress preview

3. Freehand drawing move fix
   Problem:  Dragging a selected freehand item moved the blue selection outline
             but the visual stroke stayed in its original position. Only x/y
             (bbox origin) were updated; the points array was never shifted.
   Fix:      onItemPointerMove now checks orig.kind === 'freehand' and maps
             every [px, py, pressure] point to [px+dx, py+dy, pressure].
             The origItems snapshot taken at drag start keeps orig.points stable
             so there is no accumulated drift across frames.
   Files:    app/components/board/SvgLayer.vue

4. Freehand + arrow/line resize
   Problem:  Resize handles updated bbox (x, y, width, height) but freehand
             points and arrow lx1/ly1/lx2/ly2 endpoints were left at their
             original coordinates, making the visual stroke stay fixed while
             only the selection box changed size.
   Fix:      onHandlePointerMove computes scaleX = newW / origW and
             scaleY = newH / origH after clamp to MIN size, then:
             - freehand: maps each point to [x + (px-ox)*sX, y + (py-oy)*sY, p]
             - arrow/line: transforms lx1/ly1/lx2/ly2 with the same formula
             origItems snapshot (taken at handle pointerdown) ensures the
             scaling reference stays fixed throughout the drag.
   Files:    app/components/board/SvgLayer.vue

5. Group drill-in via double-click
   Problem:  Clicking a grouped item that was already group-selected would
             immediately drill into that single item (unintuitive). Exiting
             drill-in required fully deselecting and reselecting the group.
   New interaction model:
     - Single click on grouped item (group not selected) → select all members
     - Single click on grouped item (group already selected) → stay in group
       selection; do NOT drill in
     - Double-click on grouped item → enter drill-in mode (select that one item;
       single-click navigates between members of the same group)
     - Escape while in drill-in → re-select whole group (not full deselect)
     - Escape again / click on background → full deselect
   Implementation:
     - activeDrawingGroupId ref (string | null): tracks which group is drilled
       into; null = group-selection or no selection
     - selectGroup(groupId) helper: clears selection then toggles all members
     - onItemPointerDown: branches on activeDrawingGroupId vs item.groupId
     - onItemDblClick: replaces inline @dblclick template expression; enters
       drill-in on first dblclick, opens label editor if already drilled in
     - onKeydown Escape: priority chain — rotate mode → drill-in → deselect
     - onBgPointerUp: clears activeDrawingGroupId on background click
     - watch(selectedDrawingIds): clears activeDrawingGroupId when selection
       no longer contains any member of the active group
   Files:    app/components/board/SvgLayer.vue
